# Вклад 0.3.0 — Screenpipe внутри Mac-клиента

Нативный клиент для Apple Silicon теперь содержит исполняемый файл Screenpipe.
Отдельная установка движка, Python, Rust, Ollama и локальных моделей не нужна.

- Форк: megamen32/screenpipe, коммит 737416b73938fb4d1857cd019363ecf5707a8653.
- Основа: MIT-код 892199f742e46d0c5d9e8c06687b35ca7c2b6547, до смены лицензии.
- Реиспользованы модули захвата, accessibility, OCR, JPEG и базы Screenpipe.
- Нативные кнопки начала/остановки и открытия локальных записей.
- Нет автоматической записи при запуске, аудио, открытого HTTP-порта и автоматической отправки.
- В приложение включены происхождение сборки, лицензии и уведомления зависимостей.

Проверено на M1 / macOS 26.6: 5 Rust-тестов, нативная сборка двух ARM64
бинарников, проверки URL/пути/владения процессом, подпись полного .app,
распознавание тестовой картинки настоящим Screenpipe и сохранение в его БД,
отказ от записи без разрешения ОС, загрузка настоящего HTTPS-кабинета в WebKit.
Тестовая картинка не была снимком экрана пользователя.

Ограничения этого предварительного выпуска:
- macOS пока не выдала разрешение записи экрана. Живой захват и его Stop не
  подтверждены. Разрешение включается самим пользователем для Vklad.
- Нативная запись пока не связана с веб-таймером, загрузкой сессий и ИИ-отчётами.
- Записи остаются на Mac; «Записи» открывает их папку.
- Более ранние версии macOS не тестировались; сборка без нотарификации Apple.
- Windows 0.2.0 остаётся прежним клиентом кабинета без встроенного захвата.
- В зависимостях Rust есть предупреждение о будущей несовместимости block 0.1.6.

Код клиента: 1dbc3fc6e506a94cdbfb94e8e7ddab9a5d40f10d.

## Внедрение и проверяемые результаты

На Mac установлен `/Applications/Vklad.app`, версия 0.3.0.
Внутри находится `Contents/MacOS/screenpipe-vklad`; проверены подпись полного
пакета, ARM64 обоих файлов, совпадение закреплённых исходников и Cargo.lock,
проверочная сумма вложенного подписанного бинарника.

Встроенный бинарник запускался с PATH только из системных каталогов.
На синтетическом изображении он распознал маркер SCREENPIPE CAPTURE TEST,
сохранил один JPEG и одну строку в настоящую таблицу frames базы Screenpipe.
Отдельно открытая SQLite подтвердила одну строку; это не только тестовый JSON.

Без разрешения ОС команда записи завершилась с ошибкой до создания каталога
сессии. После тестов работающего процесса screenpipe-vklad на Mac нет.
Тесты не давали разрешение macOS, не записывали экран пользователя и не
создавали пользователей или начисления в общей базе.

DMG опубликован по адресу:
https://vklad.bezrabotnyi.com/downloads/Vklad-macOS-arm64-v0.3.0.dmg

С этого адреса файл скачан на Mac в:
`/Users/user/Downloads/Vklad-macOS-arm64-v0.3.0.dmg`.
Скачанный файл побайтово совпадает с проверенным пакетом, размер 5 315 687 байт.
SHA-256: `014823f52bbfcf96d15a6b670f72b383341eabe21bb1f30c97bc18b213fe0373`.

Релиз: https://github.com/megamen32/contribution-ledger/releases/tag/v0.3.0
Форк: https://github.com/megamen32/screenpipe

Приложение не содержит пользовательских данных, ключей и файлов шрифтов.
Старый запущенный экземпляр приложения принудительно не закрывался: чтобы
увидеть новую верхнюю панель, завершите его и откройте Vklad заново.

Серверный веб-кабинет не пересобирался и не менял базу: этот этап касается
нативного Mac-клиента и страницы загрузок. Сервер продолжает отвечать health=ok.
