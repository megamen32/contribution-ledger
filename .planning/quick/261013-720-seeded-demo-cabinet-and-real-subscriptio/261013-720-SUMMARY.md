# Заполненный демо-кабинет и настоящие подписочные оценки

Демо теперь открывается как кабинет проекта с 3 вымышленными участниками, 3 задачами, отчётами и историей труда/расходов. Личный вклад 12 000 ₽; общий 24 000 ₽. Работают добавление, отметка задачи и сброс к исходным примерам. Нет landing hero и большого блока регистрации. Создание аккаунта, macOS и GitHub остаются доступны. Демо изолировано в состоянии браузера; модели и рабочие API не вызываются. README screenshots обновлены реальными снимками нового публичного демо.

Подписочный режим использует явные Anthropic-compatible маршруты Z.AI Coding Plan / glm-5.3-flash и MiniMax M Plan / MiniMax-M3.1-Flash-Preview, отдельные защищённые файлы credentials, никакого fallback. Точные модели сверены с live официальной документацией и ответами обоих провайдеров. Сохраняются requested/returned model, provider, request ID, provider response ID, usage и исходный ответ. Смена модели, пустой/обрезанный ответ, неправильная схема и чужие evidence IDs не принимаются. Ошибка валидации теперь сохраняет receipt и raw, вместо потери полученного ответа. Явный пользовательский запрос подписочных моделей имеет приоритет над прежним OmniRoute-only правилом AGENTS.

Live canary через штатный AgentBrowser server-44: в настоящем кабинете один QA-аккаунт создал задачу валидатора и утвердил отчёт, затем запустил оценку. Первая версия получила 3 оценки GLM и 3 отклонённых JSON MiniMax; исходный частичный результат сохранён и не повторялся. Наблюдённый экран сохранён и просмотрен до диагностики. Два ограниченных отдельных диагностических запроса подтвердили, что точная MiniMax отвечает и может пройти схему. JSON-template сделан синтаксически корректным, правила needs_information явными; сохранение некорректного ответа теперь проверено regression.

После выкладки исправления запущен новый round #2 (не повтор accepted slots). GLM дала 3/3 валидных assessable ответов. MiniMax: один assessable, один корректный needs_information, один ответ отклонён: null внутри duration и несовпавший packet ID. Все 6 реальных provider receipts/usage сохранены. UI показывает 4/6 assessable, partial, 0.5–1 часа, цену неизвестной; отсутствует рыночный справочник. Это подтверждает запрошенное «хотя бы немного реально работает» на обеих подписках, а не обещание стабильных 6/6. Невалидный ответ не преобразован в оценку, запрос данных не превращён в цену. Финансовое действие 0, ни одной ledger записи QA. Слот с потребностью в данных — корректный модельный результат; нестабильность MiniMax явно сохранена как ограничение.
