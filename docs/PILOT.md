# Вклад команды

Рабочий пилот для своей команды: деньги + неоплаченный труд в рублях,
зачёт стараний включён по умолчанию. Часы по согласованной ставке не зависят
от скорости моделей. Opt-out требует явно подтверждённой стоимости результата;
стоимость результата и тех же часов не суммируются.

## Запуск бинарника

```sh
./contribution init
./contribution serve
# Откройте http://127.0.0.1:8766 и введите ключ из
# ~/.local/share/contribution-ledger/team.key
```

Данные вне исходников: `~/.local/share/contribution-ledger`. `--data PATH` меняет каталог.
Ключ команды храните отдельно от репозитория и резервируйте вместе с базой.
Один общий ключ и свободный выбор участника: все честные, это не удостоверение личности.
По умолчанию сервер слушает только loopback. Для команды используйте свою VPN/HTTPS;
не публикуйте порт незащищённым в интернете.

## Что уже реализовано

- Русский браузерный интерфейс: участники и согласованные ставки, рабочие записи,
  таймер, денежные вложения, общий денежный баланс. Нет фиктивных участников и ставок.
- Таймер переживает перезапуск; после Stop остаётся черновик до подтверждения.
- Целочисленные копейки, накопительное округление, версии ставок в записях,
  идемпотентность. API поддерживает адресные возмещения и полные сторно.
- Screenpipe: локальный экспорт OCR за выбранный интервал, просмотр и загрузка
  фрагментов в карточку задачи. Никакого собственного рекордера.
- Именной черновик отчёта MiniMax, проверяемый обезличенный пакет, GLM + GPT по три
  запроса, сохранение каждого ответа и продолжение после сбоя. Пустой справочник
  ставок означает неизвестную цену, не ноль. Новая оценка — новый раунд.
- Общая очередь в SQLite, отдельный worker из того же бинарника; модели только OmniRoute.

## OmniRoute

```sh
export OMNIROUTE_BASE_URL=http://127.0.0.1:20128/v1
export OMNIROUTE_API_KEY_FILE=/protected/path/omniroute.key
./contribution worker
```

Ключ должен иметь доступ к `/v1/chat/completions`. Текущий подключённый MCP-ключ
вернул отказ `execute:completions`; успешный живой прогон НЕ подтверждён.
Ни ключи, ни тела ошибок провайдера не пишутся в журнал. К другим провайдерам
автоматического обхода нет. Ollama отсутствует.

По умолчанию суммаризатор `minimax/MiniMax-M3`, оценщики `glm-5.3,gpt-6`, по три запуска.
Изменение: `SUMMARY_MODEL`, `JUDGE_MODELS`. Сохраняются запрошенный и возвращённый ID.
Раздельные запросы не гарантируют разные веса моделей; правильность маршрутов,
качество и обход ответного кеша проверяются отдельным живым прогоном.

`rates.json` в каталоге данных — список контрактов `MarketRate`; см. схему в коде.
Каждая ставка содержит рынок, квалификацию, валюту, диапазон, источник и дату.
Не подставляйте выдуманную «рыночную» ставку. Внешние источники и договорённости
команды маркируются раздельно. Судьи не меняют финансовые записи автоматически.

## Screenpipe на ноутбуке участника

Screenpipe устанавливается и лицензируется отдельно. Текущая коммерческая версия
НЕ включена и не объявляется бесплатной для компании из пяти пользователей.

Запустите и остановите запись в самом Screenpipe, затем:

```sh
./contribution screenpipe-export \
  --from 2026-09-07T10:00:00+03:00 --to 2026-09-07T11:00:00+03:00 \
  --out session.json
```

По умолчанию читается `http://127.0.0.1:3030/search` на ЭТОМ ноутбуке, не на сервере.
При необходимости укажите `--screenpipe-key-file /path/to/key`.
Экспорт ещё ничего не отправляет команде. Просмотрите JSON, в карточке работы нажмите
«Отчёт», выберите экспорт и подтвердите загрузку. Материалы закрепляются неизменно.

**Таймер пока НЕ управляет процессом Screenpipe.** Единая кнопка записи требует
проверенного управляющего API/CLI и теста реальной остановки на конкретной ОС.
`/capture/hd/stop` выключает режим HD, а не всю запись — использовать его как Stop нельзя.
Не запускать автоматическую запись при загрузке системы.

ONNX OCR и Firecrawl AnyDoc не обязательны: OCR берём из Screenpipe; AnyDoc подключать
при появлении реального импорта PDF/DOCX. Не повторять существующие сборщики.

## Сборка и проверки

```sh
uv sync --all-groups --python 3.12
uv run pytest -q
./scripts/build.sh --python 3.12
```

На каждой ОС нативная сборка отдельно; Linux-бинарник не является приложением для macOS/Windows.
`uv.lock` добавляется после успешного реального разрешения зависимостей.
Нет CI, запускаемого платно на каждом push. Данные и ключи в git не попадают.

## Границы пилота

Учтённый денежный вклад — не юридическая доля и не право руководить командой.
Самоотчёты допустимы, обучение учитывается. Автоматическое обезличивание вспомогательное:
автор проверяет свободный текст, фактические часы, имена и личные ставки перед оценкой.
В интерфейсе пока нет редактирования прошлой работы или учётной политики; не выдавать
пилот за полностью внедрённую систему на пяти ноутбуках. Экранное видео на сервер
не копируется. Диск 3 ТБ не был обнаружен на сервере и не считается подключённым.
Резервное копирование должно быть настроено на отдельное устройство до постоянной эксплуатации.


## Проверенная поставка 7 сентября 2026

Рабочий Linux-пилот установлен на сотом сервере. Полный статус фактических тестов,
ограничений и внедрения: [docs/STATUS.md](docs/STATUS.md).
Бинарник автономный, но это Linux x86_64, не macOS/Windows установщик.
Команда `serve` открывает локальный веб-интерфейс; Screenpipe поставляется и
управляется отдельно. `init` выполняйте от имени пользователя, который запускает сервис.
