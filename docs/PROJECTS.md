# Проекты и самостоятельная регистрация

Посетитель пробует демо, затем создаёт аккаунт с названием своего проекта. Он становится администратором только этого проекта. Начальные записи и ставки пусты; правила учёта и профиль моделей создаются вместе с проектом.

На доске владелец видит «Пригласить участника». В аккаунте он создаёт одноразовую ссылку на 7 дней. Новый участник выбирает собственный логин и пароль и вступает в проект владельца. Некорректное или уже использованное приглашение не создаёт другой проект. Дубликат логина откатывает всю регистрацию, включая новый проект и расходование приглашения.

Один аккаунт принадлежит одному проекту. В рамках проекта общий дашборд показывает суммы и явно опубликованные карточки; подробная работа остаётся личной. Администратор другого проекта не получает доступа к данным или финансовым операциям. Согласованные ставки личные; правила, рыночные справочники и профили моделей ограничены проектом.

## Обновление прежней установки

Существующие участники, приглашения и настройки сохраняются в проекте `legacy`, «Команда Вклада». Финансовая история и защитные триггеры не переписываются.

Перед развёртыванием нового сервера сделайте резервную копию SQLite штатным SQLite backup API, сохраните её за пределами Git и выполните:

```sh
python3 web/prisma/migrate-projects.py /absolute/path/to/ledger.db
```

Миграция добавляет таблицу и колонки, заменяет глобальные уникальные индексы настройки на уникальные индексы внутри проекта. Её можно повторить. Не используйте `prisma db push --accept-data-loss` на рабочей базе. Затем соберите и перезапустите приложение по текущему deployment contract.

Проверки проекта: `web/tests/projects-signup.ts` — SQLite + настоящие route handlers, отдельная база с именем `test-projects-*`; старый принятый idempotency key сохраняет исходную запись, новые ручные ключи разделены по проекту и автору.
